# VideoToNo HarmonyOS 产品化执行计划

本文是从已验证 PoC 走向正式 HarmonyOS App 的顺序执行清单。除非出现阻塞性平台限制，各阶段按依赖关系推进，不跨阶段堆叠新功能。

## 当前基线

- [x] B 站二维码登录并在内存建立会话
- [x] 支持 BV、分享文本和 `b23.tv` 短链接
- [x] 获取视频信息、分 P 和 AI/人工字幕
- [x] OpenAI-compatible LLM、服务商预设、模型选择和思考强度
- [x] 三档笔记风格、长字幕分块归并、时间轴检查和阶段进度
- [x] 基础 Markdown 预览、复制和 Share Kit 系统分享
- [x] 模拟器完整链路和 HAP 构建通过

## 阶段 0：工程和产品基线

- [x] 保留 `harmonyos/` 为正式移动端工程根目录
- [x] 冻结 PoC 能力和第一版非目标
- [x] 建立领域词汇 `CONTEXT.md`
- [x] 记录关键架构决策 `docs/adr/`
- [x] 建立可持续维护的目录目标和迁移规则

完成条件：任何后续开发者能从文档判断第一版做什么、不做什么，以及代码应放在哪一层。

## 阶段 1：工程化重构

- [x] 使用 Navigation 统一应用路由，移除弃用的页面 `router`
- [x] 建立 `app / domain / data / core` 分层骨架，features 随页面 ViewModel 迁移逐步建立
- [x] 页面通过用例和 Repository 调用登录、B站内容和 LLM，不直接拼装网络请求
- [x] Repository 统一管理 B站会话、字幕、生成工作区和笔记
- [x] 建立统一错误码、用户文案和远端错误映射
- [x] 建立统一网络超时、重试和取消规则
- [x] 资源化静态用户文案、颜色和尺寸；运行时状态文案由后续本地化方案继续收敛
- [x] 为纯逻辑与 Repository 契约补充单元测试并接通测试聚合入口

完成条件：页面替换、数据库替换或接口调整不会要求同时改动多层无关代码。

## 阶段 2：安全与本地数据

- [x] HUKS 加密保存 B站 Cookie 与刷新凭据
- [x] HUKS 分 Profile 加密保存 LLM API Key
- [x] Preferences 保存多个命名 Profile、默认项与非敏感 LLM 设置，并迁移旧单配置
- [x] ArkData RDB 保存视频笔记；视频资料和生成任务表随恢复队列补充
- [x] 建立凭据删除和退出登录流程；设置页提供二次确认的清除全部本机数据
- [x] 启动时统一恢复登录状态和 LLM 配置；笔记库入口及可恢复任务留待后续阶段
- [x] Cookie 失效时删除旧会话并引导重新扫码，首版不做复杂静默续期

设备验收：API 24 Phone 模拟器已通过 HUKS 加解密/篡改拒绝、加密会话跨 Repository
恢复、Preferences 配置与 API Key 删除、RDB 笔记 CRUD/清空共 5 项 ohosTest；本地单元测试通过。

完成条件：应用被系统终止或设备重启后，用户数据安全且可预期地恢复。

## 阶段 3：正式产品体验

- [x] 首页改为本地笔记库，支持搜索、排序、重命名和删除
- [ ] 注册系统分享入口，直接接收 B 站分享链接

- [ ] 完成深色模式、字体缩放、无障碍和多尺寸适配
- [ ] 补齐空状态、骨架屏、错误页和危险操作确认

设备验收：API 24 Phone 模拟器已通过 HUKS、会话恢复、Preferences、RDB CRUD 和 RDB v2
正常/中断迁移共 6 项 ohosTest；首页完成历史笔记、空状态及失效 HUKS 凭据降级的冷启动视觉验收。

当前实现进度：应用已注册 `ohos.want.action.sendData`，可解析系统分享中的 BV、
`b23.tv` 与 `bilibili.com` 内容，并在需要扫码时保留待处理链接。本地单元测试与 debug HAP
构建通过；B站 App 分享面板端到端验证等待 HarmonyOS 真机，因此分享入口暂不勾选完成。

正式新建流程已完成第二轮改造：LLM 长期配置移入设置页，支持多个命名 Profile、默认项、预设服务商、
模型、自定义接口和思考强度；API Key 按 Profile 使用 HUKS 加密。字幕页选择 Profile 与本次笔记风格后
直接进入处理页，流程收敛为 3 步。处理页支持取消、失败重试和返回修改选项，成功后清理过期流程栈。
分 P 请求增加代次保护并在加载时禁用重复选择；登录失效前保存视频输入，重新扫码后恢复。当前已通过
单元测试、主/设备测试 HAP 构建、Profile 编辑器模拟器视觉验收；新增 Profile/HUKS 设备用例已编译，
CLI Hypium Runner 聚合仍会挂起，需通过 DevEco 单用例运行确认。完整在线生成链路待用户重新录入 API Key 后验收。

完成条件：不借助开发工具，普通用户可以独立完成首次使用和日常笔记管理。

完成条件：发布包、审核材料和隐私声明相互一致，且不存在未披露的数据处理行为。

## 执行原则

1. 功能完整性和输出质量优先；成本优化只能作为用户可选策略。
2. 不把 Cookie、API Key、字幕正文或模型响应写入普通日志。
3. 不依赖未公开的华为笔记私有接口；跨应用联动使用 Share Kit。
4. B站接口变化必须收敛在 data 层，不向页面扩散。
5. 每个阶段都必须通过 HAP 构建；涉及设备能力的阶段还必须留下真机验证记录。
